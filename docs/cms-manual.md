# ちるーむ公式サイト 更新マニュアル（microCMS）

サイトの文章・写真・お知らせ・セクションの並び順は、すべて **microCMS の管理画面** から変更できます。
HTML やプログラムを触る必要はありません。

- 前半「**サイトを更新する人へ**」は、ふだん更新する人向けです。
- 後半「**管理者向け：最初の準備**」は、最初に1回だけ行う設定です（担当: サイト管理者）。

---

# サイトを更新する人へ

## 1. 更新の流れ

1. microCMS の管理画面にログインします。
2. 「サイト設定」「トップページ」「お知らせ」のどれかを開きます。
3. 文章や写真を直して、右上の **「公開」** を押します。
4. **1〜2分ほどで本番サイトに反映されます。**

- 「下書き保存」だけではサイトは変わりません。
- 反映されないときは、ページを再読み込みしてください（スマホでは一度タブを閉じて開き直す）。
- 入力に問題があってサイトを作り直せなかったときは、**前のサイトがそのまま表示され続けます**。サイトが壊れて見えなくなることはありません。
  5分たっても変わらないときは、管理者に連絡してください。

## 2. 3つの画面

| 画面 | 何を変えるか |
|---|---|
| **サイト設定** | サイト名・団体名、検索結果の説明文、SNS 共有時の画像、LINE・Instagram・メールの連絡先、ヘッダーとスマホメニューのボタン、フッター（紹介文・見出し・先頭へ戻るリンク）、スマホ下部の固定バー |
| **トップページ** | 最初に出る大きな写真とキャッチコピー、「お知らせ」欄の見出し、各セクションの中身と並び順 |
| **お知らせ** | ヒーローのすぐ下に出る「お知らせ」。1件ずつ追加します |

各入力欄の下には、**何を入れるとどこに出るか** の説明が書いてあります。迷ったらまずそこを読んでください。

サイトに表示される文字は、**ほぼすべてこの3つの画面から変えられます**。変えられないのは次の2つだけです。
- 画面には出ず、読み上げソフトだけが読む案内（「本文へスキップ」「メニューを開く」「スライドショーを一時停止」など）
- SNS のサービス名（「Instagram」「LINE公式アカウント」「Facebook」「LinkedIn」「LINE ID」）

## 3. 書き方のきまり

### 改行
- 複数行の入力欄では、**改行したところでサイトでも行が変わります**。
- 「1行が1段落」「1行に1つ」と書いてある欄（紹介文・持ち物・こんな人を待っています など）は、**1行ごとに段落や箇条書きの1項目** になります。空の行は無視されます。

### `[[ ]]` で囲むと途中で折り返さない
スマホの狭い画面では、言葉の途中で行が変わることがあります（例:「こども／食堂」）。
折り返してほしくない語句を `[[ ]]` で囲むと、そのまとまりは途中で切れません。

```
[[こども食堂]]を、[[学生の力で]]もっと楽しく
```

- 見出し・キャッチコピー・短い文で使います。長い文全体を囲むと、かえって読みにくくなります。
- サイトに `[[` `]]` の記号そのものは表示されません。

### 空にすると出ない
説明に「空なら出しません」と書いてある欄は、**空にするとその部分ごと消えます**。
ボタンの文字を空にするとボタンが消え、Instagram の URL を空にすると Instagram の表示が全部消えます。

### URL
- URL は **`https://` から** 入れてください。`https://` 以外で始まる URL は安全のため無視されます。
- 本文の一部をリンクにしたいときは「リンクにする語句」と「リンク先」を使います。
  本文の中で **最初に出てくる** その語句がリンクになります。

### 写真
- 写真は入力欄からアップロードします。**1枚 5MB まで**。大きすぎるときはスマホで縮小してから入れてください。
- 「写真の説明（読み上げ用）」には、写真に何が写っているかを短く書いてください（目の見えない方向けに読み上げられます）。
- **顔が分かる写真は、写っている人（こどもは保護者）の許可をとったものだけ** 使ってください。

## 4. トップページのセクション

トップページの「セクション」は、**上から順にサイトに表示** されます。ドラッグで並べ替え、＋で追加、ゴミ箱で削除できます。

| セクション | 中身 |
|---|---|
| ちるーむについて | 写真2枚、紹介文、「課題と取り組み」の表 |
| 活動内容 | 写真つきの活動カード（写真なしでも可） |
| ある日の活動 | 1日の流れ。**全ステップに写真が必要**（写真のないステップは出ません） |
| 大切にしていること | アイコンつきの項目 |
| 参加の流れ | 番号つきのステップ、横の囲み、持ち物 |
| 活動の写真 | 写真のギャラリー（8枚でいちばんきれいに並びます） |
| よくある質問 | 学生向け・こども食堂や地域の方向けの質問と答え |
| 参加する（お問い合わせ） | LINE・Instagram・メールの案内、こども食堂向けの連携のご案内 |
| 団体概要 | 設立・活動場所などの表 |
| SNS | 各 SNS の説明 |
| 自由セクション（文と写真） | 見出し・本文・写真1枚。**何個でも追加できます**（新しい告知や紹介に） |

- 「自由セクション」以外は、それぞれ **1回ずつ** しか使えません（2個目は表示されません）。
- **「参加する」は消さないでください。** 消すとサイト中の「参加する」ボタンの行き先がなくなります。

### 各セクションに共通の欄

| 欄 | 意味 |
|---|---|
| 見出し | セクションの大きな見出し（必須） |
| 見出しの下の文 | 空なら出ません |
| スマホメニューでの名前 | スマホの ☰ メニューに出る名前。空ならメニューに出ません |
| パソコンの上部メニューでの名前 | パソコン画面の上部メニューに出る名前。**全部で5つまで**（6つ目以降は出ません） |
| フッターでの名前 | ページ最下部のリンクの名前。空なら「スマホメニューでの名前」を使います |
| 背景を色付きにする | オンにすると背景が薄い色になります。色付きが続かないように **交互にする** のがおすすめです |

## 5. お知らせ

- 「お知らせ」画面の右上「追加」から1件ずつ作ります。
- **日付の新しいものから5件まで** 表示されます。日付が空のお知らせ（「随時」など）は、日付つきのものの後ろに出ます。
- 古いお知らせは削除するか、「公開終了」にすると消えます。
- お知らせが1件もないときは、「お知らせ」の欄ごと出ません。

## 6. よくある更新

| やりたいこと | 手順 |
|---|---|
| お知らせを足す | 「お知らせ」→ 右上「追加」→ 日付と本文を入れて「公開」 |
| 写真を差し替える | 「トップページ」→ 写真のある欄の画像を消して、新しい画像をアップロード → 「写真の説明」も直して「公開」 |
| よくある質問を足す | 「トップページ」→ セクションの「よくある質問」→「学生向けの質問」か「こども食堂・地域の方向けの質問」の ＋ → 質問と答えを入れて「公開」 |
| セクションを並べ替える | 「トップページ」→「セクション」の各ブロックをドラッグ → 「公開」。メニューの順番も自動で変わります |
| 自由セクションを足す | 「トップページ」→「セクション」の ＋ →「自由セクション（文と写真）」→ 見出し・本文・写真を入れて、置きたい位置へドラッグ → 「公開」 |
| LINE の URL を変える | 「サイト設定」→「公式LINE の URL」を直して「公開」。サイト中の LINE ボタンがすべて変わります |

### 項目の数が文に入っているとき
「4つのこと」「3つのステップ」のように、**見出しの下の文に項目の数が書いてあるセクション** があります。
項目を足したり消したりしたときは、その文の数字も自分で直してください（自動では変わりません）。

## 7. 困ったとき

| 症状 | 対処 |
|---|---|
| 公開したのにサイトが変わらない | 2分待って再読み込み。5分たっても変わらなければ管理者へ |
| 写真がアップロードできない | 5MB 以下にする。JPEG か PNG にする |
| スマホで見出しが変なところで折り返す | その語句を `[[ ]]` で囲む |
| 上部メニューに出ない | 上部メニューは5つまで。どれかの「パソコンの上部メニューでの名前」を空にする |
| 間違えて消した | 管理画面の各コンテンツの「バージョン履歴」から前の状態に戻せます（使えるかは microCMS の契約プランによります。ない場合は管理者へ） |

## 8. 最初に確認してほしいこと（納品時の注意）

- **仮の文言が入っています。** 最初に入っている文言は、依頼時に指定されたもの（下の「依頼時に指定された文言」）を除いて、**サークルの確認を通していない制作側の案** です。公開前に全部の欄を一度読んで、正しい内容に直してください。特に次の内容は制作側の仮定です。
  - 参加費、持ち物、ある日の活動の流れ、写真の扱いについての文、ご相談の流れ
  - よくある質問の一部（特に「参加費」と「他大学の学生も参加できるか」の答え）
  - 写真の場面の説明、団体概要の活動頻度と連携先
- **ヒーローの「活動は月2回程度・参加できる日だけでOK・参加費なし・学部学年不問」** は、よくある質問・団体概要・参加の流れと同じ内容です。どれかを直したら、ほかもそろえてください。
- **依頼時に指定された文言** が入っている欄があります（キャッチコピー、その下の文、「ちるーむについて」の紹介文、活動内容の「こどもとのふれあい」の文）。変えるときはサークル内で相談してください。
- **写真はいまはすべて仮の画像** です（「写真を入れる場所」と書いてあります）。本物の写真に差し替えてください。

# 管理者向け：最初の準備

ここから先は、サイトを管理する人が **最初に1回だけ** 行う作業です。
プロジェクトのフォルダでコマンドを実行します（Node.js 22 以上）。

## A. microCMS のサービスと API を作る

1. microCMS でサービスを作ります。サービス ID（例: `chiroom`）を控えておきます。
2. 次の3つの API を作ります。**エンドポイント名は下の表のとおりにしてください**（違うとサイトが読めません）。

   | API 名 | エンドポイント | 型 | スキーマ |
   |---|---|---|---|
   | サイト設定 | `settings` | オブジェクト形式 | `cms/schema/settings.json` |
   | トップページ | `top` | オブジェクト形式 | `cms/schema/top.json` |
   | お知らせ | `news` | リスト形式 | `cms/schema/news.json` |

   API を作る画面で「スキーマをインポート」を選び、表のファイルを読み込みます。
   - インポートの代わりに、B の手順で `--create-apis` を付けても作れます。この場合、API キーに「APIの作成」の権限が必要です。ただし `--create-apis` は本物の microCMS ではまだ試していません。**まずはインポートを使ってください。**
   - どちらも使えないときは、[フィールド一覧（docs/cms-fields.md）](cms-fields.md) のとおりに管理画面で手で作ります。

## B. 今のサイトの内容を流し込む

最初は CMS が空っぽなので、今のサイトと同じ内容（`cms/seed/`）を流し込みます。

1. microCMS の「API キー」で、**一時的に** 次の権限を付けたキーを用意します。
   - settings・top: GET と PATCH
   - news: GET と POST
   - マネジメント API: 「メディアのアップロード」（`--create-apis` を使うなら「APIの作成」も）
2. 接続情報のファイルを作ります。

   ```bash
   cp cms/env.example .env
   ```

   `.env` を開いて `MICROCMS_SERVICE_DOMAIN`（サービス ID）と `MICROCMS_API_KEY` を書きます。
   **`.env` は絶対にコミットしないでください**（`.gitignore` で除外済み）。
3. 何が起きるかを確認してから、流し込みます。

   ```bash
   node --env-file=.env tools/cms/import-seed.mjs --dry-run   # 確認だけ（通信しません）
   node --env-file=.env tools/cms/import-seed.mjs             # 写真26枚をアップロードして書き込み
   ```

   - お知らせがすでに1件以上あるときは、二重にならないようにお知らせは追加しません。
   - 途中で失敗したときは、理由（権限が足りない、など）が表示されます。直してからもう一度実行してかまいません。ただし写真はもう一度アップロードされます。
4. **終わったら、API キーの権限を「GET だけ」に戻します。** サイトを作るときは読むだけで十分です。
5. 手元で確認します。

   ```bash
   node --env-file=.env tools/serve.mjs --cms   # http://localhost:3000 を開く
   ```

## C. Vercel に接続情報を登録する

Vercel の「Settings → Environment Variables」に、`MICROCMS_SERVICE_DOMAIN` と `MICROCMS_API_KEY`（GET だけのキー）を登録します（Production と Preview の両方）。

Vercel は push のたびに `node tools/build.mjs` を実行し、microCMS から内容を読んでサイトを作ります（`vercel.json` で設定済み）。

## D. 「公開」で自動的にサイトを作り直す

1. Vercel の「Settings → Git → Deploy Hooks」で、ブランチ `master` の Deploy Hook を作り、URL をコピーします。
2. microCMS の **3つの API それぞれ** の「API 設定 → Webhook」で、「Vercel」を選び、その URL を登録します。
   通知するタイミングは「コンテンツの公開・更新・削除」です。

これで、管理画面で「公開」を押すと1〜2分でサイトが作り直されます。

**Webhook が契約プランで使えないときの代わり:** Deploy Hook の URL を管理者がブックマークしておき、更新の連絡を受けたら開く（または `curl -X POST <URL>`）。Vercel の Cron で1日1回など定期的に作り直す方法もあります。

## E. 本番公開の前に

- **`photos/` の写真はいまは仮の画像** です（「写真を入れる場所」と書いてあります）。
  流し込んだ後、管理画面で本物の写真に差し替えてから公開してください。
- `master` に push すると即本番公開です。

## 開発者向けメモ

| コマンド | 内容 |
|---|---|
| `node tools/build.mjs --seed` | `cms/seed/` の見本データで `dist/` を作る（通信しない） |
| `node tools/build.mjs` | microCMS から読んで `dist/` を作る（環境変数が必要） |
| `node tools/serve.mjs` | 見本データでビルドして http://localhost:3000 で表示 |
| `node --env-file=.env tools/serve.mjs --cms` | microCMS の内容でビルドして表示 |
| `node tools/check.mjs` | 検証（スキーマ・見本データ・出来上がった HTML・壊れた入力への強さ） |

- サイトの骨組みは `site/template.html`、中身の組み立ては `tools/cms/render.mjs`、入力の点検と補正は `tools/cms/normalize.mjs` です。
- スキーマ（`cms/schema/*.json`）を変えたら、見本データ（`cms/seed/*.json`）もそろえて、`node tools/check.mjs` を通してください。microCMS の管理画面側のスキーマも同じように直す必要があります。`docs/cms-fields.md` も直してください。
- **移行中の注意:** `vercel.json` にビルド設定が入っているので、この変更を master に push した時点から、本番は「microCMS から読んで作る」になります。**A〜C が終わるまで master に push しないでください**（環境変数がないとビルドが失敗します。失敗しても前のサイトは残りますが、更新できません）。
