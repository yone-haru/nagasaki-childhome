# ちるーむ公式サイト CMS 導入 設計書

- 日付: 2026-10-18（2026-10-19 改訂: v5.0 の構成に合わせて 3.4 以降を見直し）
- 対象: v5.0（a1663a5）の静的サイト（Vercel・本番 `https://childhome-nagasaki.vercel.app/`）
- 状態: 実装中（2026-10-19、Issue #6）。v5.0 を最終デザインとして採用し、CMS を入れる

## 1. なぜやるのか

このサイトは依頼を受けて制作しているもので、納品後に更新するのは依頼主（ちるーむ側）の**非エンジニア**。今は文言1つ直すにも HTML を編集して git push する必要があり、依頼主が自分では更新できない。

**ゴール: 依頼主が、コードに触れずに、管理画面だけでサイトのほぼ全部を更新できる状態にして納品する。**

## 2. ゴール / 非ゴール / アンチゴール

### ゴール
1. サイトの**全セクション**の文章・画像・項目（FAQ の1問、活動内容の1件、写真の1枚 など）を管理画面から追加・編集・削除・並べ替えできる。
2. **セクションの並び順**を管理画面のドラッグで入れ替えられる。
3. **新しいセクションを足せる**。既存セクションの種類に加えて、汎用の「自由セクション」（見出し＋本文＋写真）を何個でも追加できる。
4. 管理画面で「公開」を押すと、**数分以内に本番サイトに自動反映**される。依頼主が Vercel や GitHub を触る必要はない。
5. サイト全体の設定（メール、LINE / Instagram 等の URL と ID、SEO 用の説明文、OGP 画像）は1か所で直せば、ヘッダー・本文・フッター・JSON-LD など全ての出現箇所に反映される。
6. 見た目は v5.0 と同等。初期データは v5.0 の文言・構成をそのまま移す。

### 非ゴール（今回やらない）
- 下書きのプレビュー（公開前に本番と同じ見た目で確認する機能）。必要になったら別タスク。
- デザイン・色・フォント・アニメーションを管理画面から変えること。
- 既存にない新しい**デザイン**のセクションを管理画面だけで作ること（それは制作側の作業）。
- ヒーロー（ページ最上部）・お知らせ帯・フッターの位置を動かすこと。中身の文言・画像は編集できるが、位置は固定。
- 複数ページ化、ブログ記事の個別ページ化。お知らせは今と同じくトップページ内の一覧のみ。

### アンチゴール（動いてもこうなったら失敗）
- microCMS が落ちている・設定ミスがある時に、本番サイトが真っ白・崩れた状態で公開される。
- 依頼主が普通に操作しただけで、レイアウトが崩れる。
- API キーなどの秘密情報がリポジトリや公開 HTML に載る。
- 管理画面が英語のフィールド名だらけで、非エンジニアが何をどこに入れればいいか分からない。

## 3. 決まっていること

### 3.1 CMS
- **microCMS** を使う。（制作側の判断。理由: 日本語の管理画面、非エンジニア向け、無料プランあり、画像アップロード・画像変換 API あり）
- アカウントは**依頼主のもの**を使う。
- 無料プラン（Hobby）の範囲で収める。公式情報（https://microcms.io/pricing）: API 5 個、メンバー 3 人、API キー 1 個、転送量 20GB/月、コンテンツ 10,000 件、画像 API 利用可。**ファイルフィールドは Hobby では使えない**が、画像フィールドは使える（今回はファイルフィールドを使わない）。

### 3.2 反映方式: ビルド時に取得して HTML を生成する
- ページを開くたびにブラウザから CMS を読みに行く方式は**採らない**。理由: キーがブラウザに露出する / 表示が遅れる / CMS 障害でサイトが空になる / `.reveal` の IntersectionObserver が後から足された要素を拾わない / JSON-LD・OGP が静的に必要。
- 流れ: 依頼主が管理画面で公開 → microCMS の Webhook が Vercel の Deploy Hook を叩く → Vercel が `node tools/build.mjs` を実行し、microCMS から全データを取得して `dist/index.html` を生成 → 公開。
- **ビルドで取得に失敗したら、ビルドを失敗させる**（Vercel は失敗したデプロイを公開せず、直前の正常な版を出し続ける）。古いデータや空データで公開しない。
- プロジェクトのルール「ビルド工程なし」は**このタスクで意図的に変更する**（ユーザーの依頼による）。ただし以下は維持する:
  - `package.json` を置かない・npm 依存を増やさない。ビルドは Node 標準機能（`fetch` 等）だけで書く。
  - フォント以外の外部依存（ライブラリ・CDN）を増やさない。
  - CSS / JS はページに内包したまま（出力される `index.html` は今と同じく1枚で完結する）。
- Vercel 側は `vercel.json` の `buildCommand` / `outputDirectory` で設定する（`package.json` なしで動くこと）。

### 3.3 秘密情報
- microCMS のサービスドメインと API キーは環境変数（`MICROCMS_SERVICE_DOMAIN` / `MICROCMS_API_KEY`）で渡す（ローカルは `.env`、本番は Vercel の環境変数）。リポジトリには入れない。`cms/env.example` に名前だけ置く（`.env.*` は権限ルールで書き込めないため、直下の `.env.example` ではなくここ）。
- 本番ビルドで使うキーは **GET 権限のみ**。
- 初期データ投入では一時的に書き込み（POST / PUT / PATCH）とメディアアップロードの権限が要る。Hobby はキー 1 個なので、同じキーの権限を一時的に上げ、投入後に GET のみへ戻す（マニュアルに手順を書く）。

### 3.4 コンテンツの構造（API 構成）

API は3つ（上限 5 個に余裕を残す）。

| API | エンドポイント | 形式 | 中身 |
|---|---|---|---|
| サイト設定 | `settings` | オブジェクト | title / description / og:description / OGP 画像（任意）、LINE の URL・ID、Instagram の URL・ID、Facebook・LinkedIn の URL、メール、JSON-LD 用の団体説明、フッターの説明文、モバイル固定 CTA の文言3つ、コピーライト表記 |
| トップページ | `top` | オブジェクト | ヒーロー（スライド写真の繰り返し・キャッチコピー・リード文・ボタン文言2つ・「こども食堂・地域の方へ」リンク文言・所属バッジ文言）＋**セクションの並び**（繰り返しフィールド） |
| お知らせ | `news` | リスト | 日付（任意）・日付の代わりの表記（「随時」など）・本文・リンクにする語句・リンク先 |

**セクションの並び**は、トップページ API の繰り返しフィールド `sections` に、セクションの種類ごとのカスタムフィールドを混在させる。管理画面ではブロックを追加し、ドラッグで並べ替える。セクションの中の項目（FAQ の1問など）は、そのカスタムフィールドの中の繰り返しフィールドで持つ（繰り返し → カスタム → 繰り返し → カスタム の入れ子は microCMS の公式ドキュメントで可能と確認済み）。

セクションの種類（v5.0 の構成）と、編集できる中身:

| 種類（カスタムフィールド ID） | 固定アンカー | 中身 |
|---|---|---|
| わたしたちのこと（`sec_about`） | `#about` | 見出し・リード・写真2枚（大・小）・本文（空行で段落を分ける）・名前の由来・「課題と答え」の小見出しと列見出し2つ・課題と答え（繰り返し） |
| 活動内容（`sec_activities`） | `#activities` | 見出し・リード・活動（写真・見出し・説明の繰り返し） |
| ある日の活動（`sec_day`） | `#day` | 見出し・リード・時間の流れ（写真・見出し・説明の繰り返し。PC の右側の大きな写真もここから作る） |
| 大切にしていること（`sec_promise`） | `#promise` | 見出し・リード・約束（アイコン選択・見出し・説明の繰り返し） |
| 参加までの流れ（`sec_flow`） | `#flow` | 見出し・リード・ステップ（見出し・説明・補足の繰り返し）・LINE のボックス（見出し・本文・ボタン文言）・持ち物（見出し・項目の繰り返し・注記） |
| 活動の様子（`sec_gallery`） | `#gallery` | 見出し・リード・写真（画像・代替テキストの繰り返し）・下部の文2つ・ボタン文言 |
| よくある質問（`sec_faq`） | `#faq` | 見出し・リード・ボタン文言・学生向けの見出しと質問（繰り返し）・こども食堂向けの見出しと質問（繰り返し）。回答は改行可、語句1つをリンクにできる |
| 参加する（`sec_join`）（内部に `#partner`） | `#join` | 上段: 見出し（改行可）・リード・写真・「こんな人に」の見出しと項目・連絡手段の注記（連絡先の URL はサイト設定から）。下段「こども食堂・地域の方へ」: 表示するか・見出し・本文・箇条書き・ボタン文言・相談の流れ（繰り返し）・メニューでの表示名 |
| 団体概要（`sec_profile`） | `#profile` | 見出し・項目（項目名と内容の繰り返し）・連絡先行の項目名（中身はサイト設定から自動） |
| SNS（`sec_connect`） | `#connect` | 見出し・リード・各 SNS の説明文（URL と ID はサイト設定から） |
| 自由セクション（`sec_free`） | 自動採番（`#free-1`, `#free-2` …） | 見出し・リード・本文（空行で段落）・写真（任意） |

共通で全セクションに持たせるもの:
- 「メニューでの表示名」（空ならメニューに出さない）
- 「ヘッダーでの表示名」（空ならヘッダーに出さない。PC ヘッダーは5個まで。6個目以降は出さずに警告）
- 「背景を色付きにする」チェック（下記 3.5）

規則:
- 「自由セクション」以外の種類は、**1 ページに 1 つまで**。2 つ置かれたら、2 つ目は無視してビルドログに警告を出す（ビルドは止めない）。
- 「参加する」セクションが無い場合でも、モバイル固定 CTA の JS がエラーにならないようにする（`join` が無いときは監視しない）。
- 「こども食堂・地域の方へ」は v5.0 どおり「参加する」の下段パネルとして出す（独立セクションにしない）。表示/非表示は切り替えられ、非表示ならヒーローの「こども食堂・地域の方へ」リンクとメニュー項目も出さない。
- 「お知らせ」は v5.0 どおりヒーロー直下の帯として固定位置に出す（並べ替え対象外）。0 件なら帯ごと出さない。

### 3.4.1 データの正規化
- ビルドスクリプトは microCMS から取得したデータを、まず内部の形（`tools/cms/normalize.mjs`）に変換してから HTML を生成する。API の形の違いはこの 1 か所に閉じ込める。

### 3.4.2 中身が不正なときの扱い
- 必須項目は、まず microCMS のスキーマ側の「必須」設定で入力時に防ぐ。
- ビルド時は、**構造的に必須なもの**（サイト設定・トップページが取れること、セクションが 1 件以上あること、LINE の URL とメール）が欠けていたらビルドを失敗させる（本番は直前の版のまま）。
- それ以外（項目の一部が空、リンク URL が不正、など）は、その要素だけを出さずにビルドログへ警告を出し、公開は続ける。
- リンク URL は `https:` / `mailto:` / `tel:` / `#` で始まるものだけ許可する。
- 文章はすべて HTML エスケープする（管理画面から HTML は入れられない）。リッチエディタは使わない（v5.0 の CSS の作法を崩さないため）。

### 3.4.3 文章内の簡易記法
- `[[語句]]` で囲んだ部分は、改行位置の都合で分けたくない語句として `<span class="phrase">` になる（v5.0 の「笑顔の輪」「こども食堂」など）。
- お知らせ・FAQ の「リンクにする語句」は、本文中で最初に出てくる箇所がリンクになる。外部リンクは新しいタブで開く（`mailto:` は除く）。

### 3.5 レイアウトが崩れないための工夫
- **背景色（`is-tinted`）**: v5.0 は厳密な交互ではない（団体概要と SNS がどちらも白）。そのため自動交互にはせず、各セクションの「背景を色付きにする」チェックで決める。色付きが2つ連続したらビルドログに警告を出す（公開は続ける）。「参加する」は独自の背景を持つのでチェックは無視する。
- **ナビゲーション**: PC ヘッダー・モバイルメニュー・フッターの3か所を、セクションの並び順と各セクションの表示名から生成する。v5.0 の出し分け（ヘッダーは5項目、モバイルは SNS 以外、フッターは全部）は、表示名とヘッダー表示名の初期値で再現する。モバイルメニューは SNS セクションを出さない（SNS 行が別にあるため）。
- **活動の様子**: 写真のレイアウト用クラス（`g1`〜`g8`）は順番に巡回して付ける。
- **件数が文言に入っている箇所**（「4つのこと」「3つのステップ」など）: 依頼主が自分でリード文を直す運用とし、管理画面のフィールド説明に注意書きを入れる。

### 3.6 画像
- 画像は microCMS にアップロードし、出力時に microCMS の画像 API（`?fm=webp&w=…`）で WebP 変換・表示枠に合わせた幅を指定する。`width` / `height` 属性も縦横比を保って付ける。
- ヒーロー1枚目の `<link rel="preload">` は、1枚目のスライドと同じ URL を出す。
- ロゴ（`chiroom-logo.png`）、大学ロゴ、favicon は**リポジトリ内の固定ファイルのまま**。OGP 画像だけはサイト設定から差し替え可能にし、未設定なら `ogp.png` を使う。
- 初期データの画像はリポジトリの `photos/` を指す（ローカル検証用）。投入スクリプトがこれを microCMS にアップロードして URL に置き換える。

### 3.7 管理画面の分かりやすさ
- フィールドの表示名・説明文はすべて日本語。各フィールドに「どこに表示されるか」「注意点」を説明文で書く。
- `改善点まとめ.pdf` で指定された文言は初期値として一字一句そのまま入れる。フィールド説明に「依頼時に指定された文言」と書いておく。
- FAQ の回答で `要確認` の2件（参加費、他大学生）は、仮の文言であることを納品時に伝える。

### 3.8 スキーマと初期データ
- 3つの API のスキーマを `cms/schema/*.json` に置き、microCMS 管理画面の「インポート」で作れるようにする。インポートが使えない場合に備え、マニュアルに手作業で作る手順（フィールド一覧）も書く。
- v5.0 の文言・構成をすべて初期データ `cms/seed/*.json`（microCMS の API レスポンスと同じ形）として用意し、`tools/cms/import-seed.mjs` で microCMS に投入する。

### 3.9 依頼主向けの更新マニュアル
- `docs/cms-manual.md`。非エンジニア向けに「よくある更新」（お知らせを足す、写真を差し替える、FAQ を足す、セクションを並べ替える、自由セクションを足す、LINE の URL を変える）の手順を日本語で書く。反映まで数分かかること、反映されないときの確認先も書く。

### 3.10 検証
- `node tools/check.mjs`（引数なし）は、初期データから `dist/index.html` を生成し、それに対して今と同じ検査（タグ対応・アンカー切れ・画像参照・`.env` が ignore されているか 等）を行う。
- 初期データから生成した HTML が v5.0（a1663a5 の `index.html`）とマークアップで一致すること（JS の null ガード追加分を除く）を差分で確認し、1440px・390px のスクリーンショットでも確認する。

## 4. ユーザー（制作者）・依頼主にしかできない作業
1. microCMS 管理画面で、スキーマ JSON をインポートして 3 つの API を作る（インポートできなければマニュアルの表に沿って手作業）。
2. API キーの権限を一時的に上げて `node --env-file=.env tools/cms/import-seed.mjs` で初期データを投入し、その後 GET のみに戻す。
3. `.env` と Vercel の環境変数に `MICROCMS_SERVICE_DOMAIN` / `MICROCMS_API_KEY` を登録する。
4. Vercel で Deploy Hook を作り、その URL を microCMS の Webhook（3 つの API すべて）に設定する。
5. `photos/` の仮画像を本物に差し替えてから master に push する。

## 5.1 出力先とファイル構成
- `site/template.html`: v5.0 の `index.html` を元にしたテンプレート（CSS / JS / アイコン SVG / ヘッダー・フッターの枠を持つ。中身は `{{名前}}` の差し込み口）。置換後に `{{` が残っていたらビルド失敗。
- `tools/build.mjs`: ビルドの入口。`--seed` で `cms/seed/` から、指定なしで microCMS から取得する。
- `tools/cms/fetch.mjs`（取得）・`normalize.mjs`（正規化）・`render.mjs`（セクションの HTML 生成）・`import-seed.mjs`（初期データ投入）。
- `cms/schema/*.json`・`cms/seed/*.json`。
- 生成した HTML と、HTML から参照されている固定ファイル（ロゴ・favicon・OGP 画像・写真 等）は `dist/` に出力する。`dist/` は `.gitignore` 済み。Vercel の `outputDirectory` も `dist`。
- 移行期間の注意: `vercel.json` にビルド設定を入れた時点で、master への push は「microCMS から取得してビルド」に変わる。microCMS 側の初期データ投入と Vercel の環境変数登録が済むまでは、master に push しない。

## 6. 実装側に任せたこと（決めた内容）
- お知らせの表示件数の上限: 5 件（仮定）。日付ありは新しい順、日付なしはその後ろに管理画面の順で並べる。日付は日本時間で表示する。
- 自由セクションの見た目: 既存の `.block` + `.sec-head` + 本文段落 + 任意の写真（`.free-photo`）。
- 開発サーバ（`tools/serve.mjs`）は `dist/` を配信する。`dist/` が無ければ初期データからビルドしてから起動する。
